# Set up the working Nuvio arrangement again

There are two different backups. Keep them separate.

| File/tool | What it contains | Where it belongs |
| --- | --- | --- |
| Public repository ZIP | Generic tools, templates and instructions | GitHub; safe to share |
| Your private Windows vault | Captured configured addon links and saved credentials, plus layout/settings | Your computer only; encrypted for the Windows user that created it |
| Your portable encrypted backup | The private snapshot encrypted with your chosen password | Private backup storage; keep the password separately |
| A layout import generated by either tool | Collections, Home and the selected saved settings, without addon links/provider keys | Import into your selected profile; keep private |

**Do not use an exported Kaptain backup as your only credential backup.** Kaptain's snapshot/export code deliberately redacts addon credentials. We verified a real failure where `realdebrid=REDACTED` ended up installed. That literal word is not a token. An exported placeholder alone does not prove a live URL is broken: inspect the installed URL in Nuvio before changing it.

## Choose your situation

- **Another device, same account/profile:** sign in to Nuvio and select the existing profile first. Do not reinstall all addons by default. Check whether the profile and its connections sync.
- **A new profile or a damaged layout:** restore the private layout file, then restore any missing connections from your vault using the copy buttons. Check the exact target profile each time.
- **A new computer or Windows reinstall:** use the portable encrypted backup with `recovery/portable.html`. The Windows-only vault cannot be relied upon after an OS reinstall or under another Windows user.
- **First installation with no working snapshot:** use [simple-config](https://github.com/AMurtadaa/nuvio-community-config/tree/simple-config) for no-VM collections, or the [Oracle guide](oracle-service-shelves-setup.md) for cached service shelves. You must supply your own services and credentials once. This recovery tool does not invent an initial credential backup.

## Your private Windows kit: everyday use

1. Open the private kit folder saved on your computer.
2. Double-click **OPEN MY NUVIO BACKUP.cmd**. It opens the local helper with your Windows-encrypted vault. The launcher needs its saved Node runtime and helper source paths to remain available.
3. Check the coverage message. A missing credential is explicitly marked MISSING. Captured URLs are not a guarantee that every provider works: disabled/unfinished entries remain disabled/unfinished in the saved snapshot.
4. Add a missing TMDB key once in the local field and press **Save encrypted backup**. Use the TMDB **API Key (v3 auth)**, not the longer read-access token in a key-only field. Saving here changes only the local vault.
5. Create a **portable encrypted backup** using a strong, unique password of at least 12 characters. Save that file privately and keep the password somewhere separate. There is no recovery/reset for a forgotten backup password.

The Windows vault uses DPAPI CurrentUser. The portable file uses AES-256-GCM with a fresh salt/IV and PBKDF2-SHA256 (600,000 iterations). These are two alternative forms of the snapshot, not two factors. Someone using your unlocked Windows account can open its local vault. Do not distribute private files with the public repository.

The local helper listens only on `127.0.0.1`, requires an unpredictable unlock token for private API calls, refuses foreign origins/hosts, and does not send account data to an external service. A failed or expired launcher link can be regenerated by starting the helper again. Close its process when finished.

## Restore on this computer or a new one

### 1. Open your private snapshot

On the original Windows account, use the private launcher. Otherwise:

1. Download [the main repository ZIP](https://github.com/AMurtadaa/nuvio-community-config/archive/refs/heads/main.zip).
2. Extract the whole ZIP. Do not open files from inside the compressed archive.
3. Open **recovery/portable.html** in a current Chrome, Edge or Firefox browser.
4. Choose **my-nuvio-portable.encrypted.json** and enter the backup password.
5. Click **Unlock locally**. It reads/decrypts the file on that computer, makes no network requests and does not sign in to an account.

The companion `.cjs`, `.js` and `.css` files must remain alongside the HTML. A wrong password or modified encrypted file fails without importing anything. Clipboard support for local files varies by browser; use the Windows localhost helper if local-file clipboard access is blocked.

### 2. Restore folders, Home and settings

1. In [Kaptain Studio](https://kaptain.stream/studio), select the **target** profile and export its existing backup first.
2. Find its numeric `profileId` in that export. A profile name is not an ID.
3. In the private helper, enter that target ID, confirm the replacement warning, and download the layout import.
4. In Studio → **Backups & Updates → Import backup file**, select the new layout file. Restore that imported item and read the proposed changes before applying.
5. The private layout file replaces its included collection, Home and saved-settings sections. It contains no addon list or provider credentials. Unrelated watch history is excluded.

The public **recover.html** tool is a more conservative alternative: it can build a collections-only recovery from a normal Kaptain export. Home and supported appearance are optional; playback, provider groups and keys are omitted. It flags redacted addon links, never includes them in the import, and cannot verify live credentials.

### 3. Restore addon connections without retyping keys

1. Open [Nuvio's account website](https://nuvio.tv/account), sign in yourself, and select the target profile.
2. Open **Addons**. Keep an already working matching entry.
3. For a missing/broken entry, use the helper's **Copy configured URL** button. It copies the complete private URL, including any embedded credential. The URL is not shown on the helper's page.
4. Use **Edit** for an existing entry or **Add Addon** if it is missing. Paste the URL and save. Do not replace a similarly named but different addon accidentally.
5. Preserve order and enabled/disabled state. A duplicate entry may have different filters; do not remove it merely because the names look similar.
6. Do **not** put credential-bearing addon lists through Kaptain's snapshot/import path. Its redaction step defeats the point of the private snapshot. Use Nuvio's own addon controls.

This is guided recovery with copy buttons, not a one-click cloud restore. It avoids re-entering individual tokens, but the account website still requires saving each missing configured addon. No account login cookie/password is included or bypassed.

### 4. Restore native metadata connections

On Windows Nuvio: **Settings → General → Integrations → TMDB Enrichment**. Copy the saved TMDB key from your helper, paste it into Personal API key and Save. Check each profile that uses native TMDB folders. Do not assume that copying rows and addon names also copied a working native key.

For Real-Debrid-configured Torrentio links, the embedded token is already in the saved configured URL. Nuvio's own Connected Services connection is separate; configure it only if your setup uses that path. OAuth integrations such as Trakt may require signing in again. The kit does not capture OAuth sessions, Nuvio login passwords, SSH keys or VM secrets. Other API credentials are covered only if deliberately saved or embedded in the captured links; the tool does not claim to extract every secret from an app.

## What makes up the complete arrangement

| Part | Purpose | What a profile restore does |
| --- | --- | --- |
| Collections and Home | Streaming-service folders, categories and row order | Restores saved definitions and IDs |
| Native TMDB / other catalog connections | Genres, Mood & Vibes, Based on and other native queries | Requires valid target-profile connections |
| Playback addons + Real-Debrid | Source lookup and playable links | Restore your configured links and keep subscription active |
| Bttr/custom poster pattern | Styled posters with IMDb labels | Saved profile settings; upstream availability still matters |
| Service Shelves host | Small cached service catalogs | Existing HTTPS host must stay running; profile import does not deploy it |
| Optional poster/chart caches | Cached/resized art and repaired numbered charts | Existing host/routes must remain available; source providers control freshness |
| Each Nuvio client | GIFs, hero/banner, focus, scrolling, playback | Test Windows, TV and phone separately; one preset cannot force identical client behavior |

For VM rebuilding, follow the [Oracle setup guide](oracle-service-shelves-setup.md). Maintain a separate private server backup of service configuration, Caddy configuration and secrets. Keep the source URLs and cached-addon IDs consistent with folder references. Do not overwrite Caddy with an old backup that removes newer routes. The private profile vault is not a VM disaster-recovery image.

## Final checks, on each profile/device

1. Genres shows titles.
2. Mood & Vibes and Based on show titles.
3. A streaming-service folder has its intended categories and Top 10 rows.
4. Numbered chart art loads and the chart count/order is sensible.
5. Your intended source addon returns results; a title plays without an RD error.
6. Static posters, hero/banner and focus GIFs behave as intended on that client.

If native folders fail but hosted service shelves work, check the native TMDB connection first. If only one addon says invalid RD token, inspect that installed URL first. If all profiles fail on the same addon, check its shared credential/provider before changing folders. If hosted catalogs or images fail together, check the host; do not replace your Real-Debrid token to fix a metadata outage.

Keep the original target backup until these checks pass. Recover layout and credentials separately: restoring a redacted backup is not credential recovery. Refresh your private snapshot after rotating keys or changing addon configurations; a backup cannot keep a revoked token working.

## Developers: creating a first private Windows vault

`recovery/server.mjs PRIVATE_FOLDER` opens an existing `private-backup.vault` using Node 20+ on Windows. `recovery/windows-vault.ps1` seals JSON from standard input with `-Mode Seal -Path PRIVATE_FOLDER/private-backup.vault`; Open returns decrypted JSON to its caller. Never run Open in a terminal where its output would expose real credentials. The local server consumes it privately through a pipe.

The private payload schema is `format: nuvio-private-recovery`, `version: 1`, `savedAt`, `layout` (a Kaptain backup without addons or credential fields), `addons` (ordered objects with name/url/enabled), and `credentials` (tmdb and realDebrid). A trusted local capture process must provide actual current URLs from the account UI, not redacted exports. Generic readers and encrypted restoration tools are public; account snapshots never are. Synthetic crypto tests contain no real credentials.
